# Setup Guide (new developer)

## 1. Required software
- Node.js 20 or newer (Vite 7 / TypeScript 5.8 toolchain)
- Bun (used in this project's dev environment; `bunfig.toml` is present) — npm works as well
- Git
- A code editor with TypeScript support

## 2. Prerequisites
- Access to the Lovable project (the backend, secrets and publishing are managed there)
- A value for `OPENAI_API_KEY` — without it every AI feature returns a German "service unavailable" message
- Optional: `FIRECRAWL_API_KEY` for external ratings

## 3. Get the code
```bash
git clone <repository-url>
cd <project-folder>
```
(In Lovable, use the project's GitHub export/sync.)

## 4. Install dependencies
```bash
bun install
# or
npm install
```

## 5. Environment setup
`.env` in the repository is auto-generated by the Lovable Cloud integration and holds only the Supabase URL, project id and publishable key (`VITE_*` plus server duplicates). Do not edit it manually.

Runtime secrets are **not** in the repository and must be provided by the environment:
`OPENAI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `FIRECRAWL_API_KEY` (optional).
See `ENVIRONMENT.md` for the full list. In Lovable these are managed as project secrets; locally, export them in your shell before starting the dev server.

## 6. Database setup
The schema lives in `supabase/migrations/*.sql` and is already applied to the connected Lovable Cloud project. For a fresh Supabase project, apply the migrations in filename order:
```text
20260514093255_*.sql   # trip_requests, packages, affiliate_clicks + RLS
20260514093318_*.sql
20260519061831_*.sql   # drops the public insert policy on affiliate_clicks
20260519061854_*.sql   # profiles table, triggers, function grants
20260525043059_*.sql   # drops the public read policies on trip_requests/packages
```
No seed data is defined in the project.

## 7. Development commands
```bash
bun run dev        # start the dev server (http://localhost:8080)
bun run build      # production build
bun run build:dev  # development-mode build
bun run preview    # preview a build
bun run lint       # ESLint
bun run format     # Prettier
```

## 8. Start the application
```bash
bun run dev
```
Open `http://localhost:8080`.

## 9. Stop the application
Press `Ctrl+C` in the terminal running `bun run dev`.

## 10. Run tests
No test framework is configured — see `TESTING.md`. The only script-style check is `scripts/test-30days.ts`, an ad-hoc script.

## 11. Common setup problems
- **Chat answers "KI-Dienst ist derzeit nicht verfügbar"** → `OPENAI_API_KEY` is missing or the account has no credits.
- **Packages are generated but nothing is stored** → `SUPABASE_SERVICE_ROLE_KEY` missing; persistence errors are swallowed by design and the UI still works.
- **No ratings on packages** → `FIRECRAWL_API_KEY` missing, or the 5 s ratings budget expired. Expected behaviour.
- **Import errors after editing `src/routes/`** → `src/routeTree.gen.ts` is generated; never edit it, it regenerates on dev/build.
